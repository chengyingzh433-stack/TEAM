## 交付语义

归档是含 `manifest.json` 的独立目录。可以完整复制或自行压缩搬移；本批导入选择解压后的目录，不接收 ZIP。manifest 固定 schema、流程版本、原课题 ID、输入版本、目标、文件相对路径、用途、原始记录 ID、字节数、SHA-256 和缺项／取得方式。`index.html` 提供相对文件链接及缺项清单。

导出前逐项勾选允许分发的来源、数据。没有勾选不推定许可：原文不复制，数据及包含该数据的分析输入副本和复算目录不复制。课程库原文和图像不分发，记录固定知识版本、指纹与方法条目位置；缺项明确说明重新取得方式。用户研究文件、课程库、原项目与失败产物不删除或覆盖。

实际打包范围：

- 已许可来源／数据的固定字节及指纹；当前材料之外的历史引用列为缺项。
- 原稿、修订、审阅的正文与角色／版本／引用；不复制原生会话或整份应用状态。
- 固定分析计划、实际结果、审阅、数字绑定、决定及非数值分析记录。未经许可的原文逐字片段不随包分发；综合记录含未许可来源片段时列缺项，原主稿与审阅仍保留。
- 已许可数据对应的旧分析四文件／登记分析六文件复算目录。输入、参数、登记计划／结果及已固定脚本指纹核对；结果文件的自身路径改成包内相对位置，原结果值不改。
- 已接受、审阅和旧版交付的 Markdown／HTML／DOCX，关联原稿身份及交付状态。先核对原稿溯源，Markdown 和具备固定指纹的 DOCX 再核对字节。没有可用溯源的历史包列缺项，不冒充固定稿。原全量溯源文件不照搬，归档内 `records.json` 使用本课题记录的显式字段投影。

整个项目先克隆，再读取真实文件。输入内容变化或指纹不符会拒绝导出，不以“成功但混版”交付。文件缺失明确进入缺项。文件全部写完后最后写 manifest，再由协调器登记；独立目录和排他创建保留旧包与失败证据。

## 安全导入与新课题

导入先验证完整目录、schema／流程版本、大小、路径、所有登记文件字节及 SHA、研究记录与清单身份一致性，再使用固定的验证后字节复制。拒绝绝对路径、`..`、反斜杠、Windows 设备名、大小写路径冲突、符号链接、未知文件／目录、文件用途不匹配、超限文件、版本不支持或指纹不符。文件读取有大小上限和实际 inode／读取前后状态检查。

目前限制：最多 2000 个登记文件、单文件 32 MiB、总文件内容 256 MiB、manifest 2 MB。只接受产品规定的归档路径布局。SHA 用于检测完整性，不证明第三方归档作者身份；复算脚本始终作为文件保存，产品不会自动执行。

校验通过后先写独立临时目录，完整落盘再 rename 到新 UUID 目录；之后创建新课题的四个独立会话，最后通过原有状态持久化队列一次登记课题。导入或状态保存失败不登记半个项目、不报成功；已形成的暂存文件或未登记会话保留，不清理失败证据。

同名课题重复导入产生不同项目／会话／目录。原 ID 到新 ID 的映射为新项目 `id` 与 `archiveOrigin.sourceProjectId`；后者同时记录原输入版本、manifest 指纹及本地归档目录。归档中材料、稿件和分析的原 ID 由 manifest `originalId` 保留在原项目命名空间，不混入当前任务身份。

新课题为 revision 0／paused。历史正文、来源、结果和决定可从“打开归档目录与缺项”读取；不把旧审阅登记成新课题有效审阅，不恢复原生请求或预算，也不复制原模型／全局配置。直接“恢复”会提示先核对归档，并在导师会话明确新任务。后续研究仍使用现有材料导入／采用流程，把需要的随包材料明确采用后开始；本批不是原会话原地恢复功能。
