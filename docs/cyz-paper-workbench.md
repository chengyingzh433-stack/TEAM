## 原功能与使用路径

这套工作流面向中文教育研究初学者，尤其适用于物理教学、科学教育及学习科学。三类入口为：没有想法时做方向探索；已有教学困惑或研究想法时直接打磨问题；已有论文、数据或稿件时先盘点材料，再补最早缺失的研究条件。继续项目先读 `00-项目状态.md`，不因换会话而从头重做。

| 阶段 | 工作内容           | 主要成果或验收依据                                     |
| ---- | ------------------ | ------------------------------------------------------ |
| S0   | 领域扫描与灵感发现 | 检索记录、WHY/HOW/WHAT 扫描、候选方向与用户选择        |
| S1   | 实践问题与研究问题 | 研究问题、范围、替代解释、可行性、决策与修订记录       |
| S2   | 文献检索设计       | 中英文检索式、来源、纳排标准和可复现检索记录           |
| S3   | 文献筛选与分级阅读 | 筛选记录、文献卡、原文定位、有效 PDF 阅读缓存          |
| S4   | 文献综合与研究缺口 | 文献证据矩阵、共识与分歧、针对候选缺口的反证检索       |
| S5   | 研究设计           | 问题—证据—方法—分析的对应表、样本与伦理方案            |
| S6   | 数据收集与分析     | 真实数据来源、处理记录、分析结果和不确定性             |
| S7   | 论文写作           | 有证据的 Markdown 主稿、语言打磨基线、语义锁和人工复核 |
| S8   | 全文审查与正式输出 | 证据与引用审查、未解决问题、审定版本与输出一致性       |

研究主张区分「已核验」「待核验文献」「研究者推断」「AI建议」「待补材料」「不可使用」。题录或摘要不能冒充全文核验；没有检索到不能直接写成研究空白；不能编造引用、数据或伦理审批。

## 外部条件

- 模型通过 Lancer/Pi 已配置的服务使用，不依赖 Codex 登录或 `$cyz-edu-research` 命令。
- 在线文献检索仍需要当前模型可用的联网工具、公开接口或用户提供的材料；数据库权限不能凭工作流获得。
- 初始化、项目检查和语义锁脚本使用 Python 3。脚本检查不能代替学术判断和人工语义复核。
- 中文 `humanizer-zh` 和英文 `humanizer` 的固定说明资源随本模式携带，只在写作语言环节读取，不注册为全局技能。
- 原 MinerU Desk 说明面向 Windows。macOS 不执行其 Windows 安装步骤，也不声称 Desk 可用；优先复用合格缓存、原始 Markdown/HTML 或已核验材料，PDF 转换需要可用后端或明确选择并记录限制的备用方案。不会自动上传文献。
- Word/PDF/PPT 导出仍需相应环境；本次不移植配套 Windows 桌面工作台的材料管理器、数据库、PDF 阅读器或 Codex 任务系统。

## 后续加入个人想法

右键「CYZ 论文工作台」进入模块管理，可调整默认阶段、模型、目标和交付要求；新会话继承新模板。会话顶部的流程设置只修改该会话，已经保存的流程不会被模板修改覆盖。内置指导标注到各阶段，修改阶段名称不会误用其他阶段规则；需要完全自定义时可以移除该阶段的内置指导。

## 在 Lancer 中使用

1. 在自己的研究项目目录打开工作区，选择左侧「CYZ 论文工作台」，新建会话并描述现状。可以直接说「我没有选题」「我发现学生会套公式，但讲不清适用条件」或「继续这个项目」。首次发送会带入入口识别与项目续接指导，不要求输入 Skill 命令。
2. 点会话上方流程设置，查看九阶段目标与交付物。可以用「为未配置阶段选择模型」一次填充，再为不同阶段单独选择不同模型。没有可用模型时需先在 Lancer 中配置自己的模型服务。
3. 点击要推进的阶段，再点「载入任务」。任务会带入该阶段的目标、交付物、详细规则和可读取的本地资源路径。检查后发送；非空草稿会阻止载入，避免覆盖尚未发送的内容。
4. 持续项目沿用自己的项目记录和主稿，标准新项目使用 `00-项目状态.md` 及相关 Markdown。单次阅读或文字修改可直接交付结果。可以跳到当前所需阶段，模型只核对本轮需要的前置条件；阶段高亮表示当前模型交接，不表示学术审查通过。
5. 先在模块管理中改默认模板，可让后续新会话采用自己的想法；已经保存的会话仍使用自身流程。详细参考、模板及脚本也随应用保留，模型可按阶段读取。

配置模型、切换阶段、保存模板和载入草稿本身不发起研究请求。点击发送才使用所选模型服务。实际检索、PDF 处理或导出是否成功，需依据对应工具的真实结果判断。

## 内置流程如何工作

截图中的编辑器原本保存阶段名称、负责模型、技能路径、目标与交付要求；点击阶段使用原会话切换模型，点击「载入任务」把要求放入草稿，用户发送后由 Pi 执行。它没有独立的自动研究调度器，也不会因模型完成回复而自动进入下一个阶段。

CYZ 在这条现有路径上增加两层内容：新会话首次发送时附加入口识别和项目续接规则；每个阶段绑定稳定的指导标识，载入任务时由主进程读取 Lancer 专用的阶段说明并放入草稿；原始 Skill 参考仅列出路径，由模型按本轮需要读取。改名称、调整目标或删除其他阶段不会让指导错位。资源路径只由应用提供，界面不能传入任意读取路径。

默认模板在 `contracts/cyz-paper-workflow.ts`；宿主适配在 `resources/workflows/cyz-lancer-guide.md`，逐阶段说明在 `resources/workflows/cyz-stages/`；原始参考、模板和脚本放在资源目录中，保持原文件哈希。这样以后可以分别调整界面流程、执行约定和研究方法，不必修改 Pi 的运行时或账号逻辑。
