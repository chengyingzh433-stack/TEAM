# S7 · 约定范围的写作与语言检查

先区分起草、实质修订和语言润色，确定本轮章节或段落及主稿版本。已有文字的局部改写无需重新做选题和全文研究设计；仅在相关主张缺乏依据或与材料矛盾时指出问题。开题或计划使用计划语气，不虚构已经取得的结果。

先理清论点与证据，再处理语言。保留用户观点和作者声音；每个文献主张与实证主张使用适当的来源或数据，缺项用清楚的待补标注。用户指定的文件和格式优先，不强制把已有主稿迁为 Markdown；标准项目可用 Markdown 工作稿。

实质内容稳定后，中文按需读取随包 humanizer-zh 及其模式参考，英文读取 humanizer，混合稿按段落语言处理；它们是本地参考资源，不是待安装的技能。依赖不可读时说明限制，不宣称已执行其语言检查。只修改约定范围，不自动把局部润色扩大为全文语言工程。保留数字、术语、引文、条件、否定、不确定性和因果强度；不判断作者身份或承诺通过 AI 检测。

保留改写前后版本，逐项对照事实和含义。适用于文件改写时可用 `cyz-edu-research/scripts/check_semantic_lock.py <基线> <改写稿> --language zh|en --skills-root <资源根目录> --dependency-lock <资源根目录>/dependencies.lock.json` 辅助核对；没有适用文件、依赖缺失或用户跳过时如实说明，仍可检查已有文字。脚本和模型对照不能被记成人工已复核，哈希相同也不证明学术结论正确。

交付本轮草稿或修订稿、主要改动、检查范围与待复核项。若主稿在检查后改变，仅重查受影响内容及关联主张，旧检查不能代表新版本。持续项目再把版本和检查结果记录到已有写作或审查文件。
